# 版本与弃用

## 一、当前 0.x

- 版本格式 `0.MINOR.PATCH` 是**当前格式**。当前没有发布 1.0 的必要，不承诺 1.0；将来若有必要，重新评估即可——这不是永久决定。
- `MINOR` 是唯一的功能单位；`PATCH` 只修不增——不得引入新能力、不得改契约。
- 破坏性变更在 0.x 允许（semver 允许），但**同一 MINOR 内必须附迁移**（脚本或文档），且路线图里有对应条目。**不允许「只破不给路」。**

## 二、每个 MINOR 的准入条件

四条全满足才能发：

1. **不变量一条没破** —— [invariants.md](invariants.md) 的 conformance 测试全绿；
2. **至少一条能力增量** —— 来自能力池，不是重构；
3. **弃用管道最多前进一步** —— 不许一个 MINOR 里既引入又移除；
4. **可回滚** —— 本 MINOR 的数据回到上一 MINOR 至少能读；做不到就提供回滚迁移。

## 三、弃用管道

四步，每步至少隔一个 MINOR：

```
引入 → 并存并告警 → 迁移工具可用 → 移除
```

| 步骤 | 状态 | 要求 |
| --- | --- | --- |
| 引入 | `introduced` | 新面可用，旧面仍可用 |
| 并存并告警 | `deprecated` | 新旧同时可用；用到旧面时运行日志告警一次（不刷屏） |
| 迁移工具可用 | `migratable` | 提供脚本 / 文档，把旧数据或旧调用迁到新面 |
| 移除 | `removed` | 旧面消失；**移除前必须有迁移工具** |

**这条管道就是你的「稳定性」。** 0.x 本身不承诺稳定，稳定感由「破之前永远先告警、永远先给路」提供。

## 四、未完成的能力

- 未完成能力走 **feature flag**，不进默认路径，**禁止长分支**；
- 每个 0.x 必须可发布、可回滚，包括半成品；
- flag 名与路线图条目 id 绑定，避免 flag 变成幽灵。

## 五、和路线图的关系

版本号不手写。`docs/roadmap/1.x-开发.md` 的路线增量是条目事实源，版本路线图从它派生：

```
路线增量 → 状态流转 → 版本分配 → changelog / release notes → 下一个 MINOR 准入检查
```

见 [../roadmap/1.x-开发.md](../roadmap/1.x-开发.md)。
