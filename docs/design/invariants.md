# 不变量

九条。每条都必须落成**可执行测试**，不是文档里的一句话。不变量被破 = 这个 MINOR 不能发。

| # | 不变量 | 违反后的症状 |
| --- | --- | --- |
| I1 | 模块互不依赖，跨模块只经总线调用平面 | 「全流通监控」开始说谎 |
| I2 | 权限判定唯一入口，三态不塌陷为 bool | `if decision:` 埋雷；默认策略不可审计 |
| I3 | 内核四层单向 `config → log → storage → bus` | 循环依赖，拆不开 |
| I4 | 一切持久化数据带 `version` + `migrate()` | 第二次改格式就锁死 |
| I5 | 状态变更先写事件日志，后落数据 | 崩溃后无法解释数据从哪来 |
| I6 | 任何跨模块调用携带 `Subject` | 以后加分享 = 全面改签名 |
| I7 | 内核不知道 UI 存在 | UI 换不动 |
| I8 | 事件封套是内核资产，传输只是绑定 | 换传输时要重做一遍 |
| I9 | **APP 不得做未授权动作** | 用户炸 |

---

## I1 模块互不依赖

- **内容**：组件之间不得直接 `import`；跨模块调用只经总线调用平面 `invoke`。
- **为什么**：`docs/roadmap/1.x-开发.md` 的「全流通监控」只有在所有跨模块调用都走总线时才成立。允许直接 import，监控就开始说谎。
- **测试**：静态——组件包之间零 import（AST 扫描或分层白名单）；运行时——总线代理的调用计数等于实际跨模块调用数。

## I2 权限唯一入口，三态不塌陷

- **内容**：`guard(subject, action, obj) -> Decision`，`Decision ∈ {ALLOW, DENY, UNCERTAIN}`；调用点不得把它转成 bool。
- **为什么**：`if decision:` 的真值取决于枚举定义，是最阴的一类 bug；「不确定时的默认值」由调用点随手给就不可审计。
- **测试**：AST 检查——`Decision` 值不得出现在 `if` / `and` / `or` / `bool()` 位置；运行时——`Decision` 的 `__bool__` **抛 `TypeError`**。

  > **注意（2026-10-16 更正）**：本条原先写"`Decision` 不实现 `__bool__`"。这是个**反的**假设：枚举不实现 `__bool__` 时走默认对象真值，`bool(Decision.DENY)` 恒为 `True`，于是 `if decision:` 对 DENY 也进真分支——正是本条要防的静默错误。故改为显式抛错，把静默错误升级为立即崩溃。

## I3 内核四层单向

- **内容**：`config → log → storage → bus`，下层不得知道上层。
- **为什么**：反向依赖会锁死拆分，也锁死「内核不含业务语义」。
- **测试**：import 方向检查（分层白名单）。

## I4 持久化数据带版本与迁移

- **内容**：任何落盘文档带 `version`，且注册了 `migrate(from, to)`。
- **为什么**：第二次改格式就锁死。
- **测试**：conformance——每个已注册文档类型都能从最低版本迁到当前版本。

## I5 先写事件日志，后落数据

- **内容**：变更顺序固定为「事件日志 append → 数据落盘」。
- **为什么**：崩溃后要能解释「数据从哪来」。
- **测试**：故障注入——在数据落盘前杀进程，重启后日志里必须已有该事件。

## I6 跨模块调用携带 Subject

- **内容**：任何跨模块请求都带 `Subject`，哪怕当前只有本机单用户。
- **为什么**：以后加分享就是全面改签名。
- **测试**：总线层校验——缺 `subject` 的调用直接拒。

## I7 内核不知道 UI 存在

- **内容**：内核不得 import 任何 UI 代码，不得出现 UI 概念。
- **为什么**：UI 是 Tauri WebView，换它不该动内核。
- **测试**：import 方向检查 + 关键词扫描（视图 / 渲染 / 按钮）。

## I8 封套归内核，传输是绑定

- **内容**：事件与命令的封套（字段、版本）由内核定义；Tauri IPC / stdio / 本地套接字只是绑定。
- **为什么**：换传输不该重做一遍封套。
- **测试**：换一个传输实现，封套与协议测试全部复用通过。

## I9 APP 不得做未授权动作

- **内容**：APP 不得自己开浏览器、**自己起对外服务**、自己弹窗、**自己联网**。一切**面向用户或面向外部**的动作由用户显式发起。
- **为什么**：这是本体的前提——用户双击就要能用。软件不好好干活、自己瞎开，这叫未授权动作，用户会炸。普通用户不是技术大拿。

### I9 的边界（2026-10-16 修订）

原文写的是"自己拉进程"，与既定打包路线（**Python 核心作为 Tauri 的 sidecar**）直接冲突：宿主拉起自己的核心进程是 **APP 的内部实现**，用户感知不到，也没有任何东西被"擅自打开"。所以判据从"有没有拉进程"改成**"这个动作是否让用户被动承受了他们没要的东西"**：

| 允许（内部实现） | 禁止（未授权动作） |
| --- | --- |
| 宿主拉起**自己的** sidecar 核心进程 | 拉起第三方程序、shell、用户没要求的工具 |
| 同一条 sidecar 的 stdio / 命名管道通信 | **监听 TCP 端口**、起 HTTP 服务、对外可连 |
| 读写自己的数据目录、附件库 | 联网、上报、检查更新（除非用户点了） |
| 由用户操作触发的弹窗、打开文件 | 启动即弹窗、启动即开浏览器 |

**"对外"是关键词**：进程内通信、生命周期由宿主掌握的子进程，不算对外。**任何监听端口或联网一律禁止**，没有例外。

- **测试**：静态——内核与组件不得调用 `webbrowser` / 监听端口 / 发起网络请求；`subprocess` **仅**允许出现在 sidecar 宿主一侧且目标是自身核心（不在内核四层内）；运行时——集成测试断言不存在**监听 socket**，且开启前后进程数增量为 0 或仅为自身 sidecar。

  > **落地状态**：内核（`src/lurnia/core/`）当前仍**零** `subprocess`，所以静态检查维持原样从严；放宽只发生在 sidecar 宿主那一侧，届时按上表加白名单，不整体松绑。
